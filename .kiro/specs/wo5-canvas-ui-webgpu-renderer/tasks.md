# WO-5: Tasks

Per `model-routing-protocol.md`: this Work Order contains the third and final of the project's three CAT 5 tasks — arguably the hardest single task across the whole build (least precedent to lean on).

- [x] [CAT 1] Audit `client-apps/web/src/data/aceTopology.ts` against the real Miranda-Engine crate set; update node definitions to match (currently reflects the old eve-ecc node set: mic/presence/syncer/riva-asr/nemotron/riva-tts/a2f/animgraph/omniverse). — Done. New 9-node set: mic, presence, cloud-bridge (ace-controller/Pipeline 1), native-capture (miranda-audio), ipc-bus (miranda-ipc), supervisor (miranda-supervisor), kinematics (miranda-nodes), transport (miranda-transport), renderer (WO-5 WebGPU viewport, not yet built). NodeKind and EdgeKind unions rewired in types.ts; KIND_GLYPH record forces compile-time completeness. liveIndicators.ts's GPU-weight table and id-branching logic, transitions.ts's controlPlaneReady, run.mjs's healthFor/nodes array, and presence_kit.mjs's NODE_INTEL all rewired in lockstep. Verified: tsc --noEmit clean, vite build clean, ace-controller /v1/status and /v1/nodes confirmed serving the new ids over a real HTTP request.
- [x] [CAT 3] Rewire `src/lib/ace/controllerClient.ts` and `spatialSyncer.ts` to speak to the new WO-4 Rust WebSocket telemetry server instead of the old Node.js `ace-controller`. — Done as a new module `mirandaTransport.ts` alongside (not replacing) `controllerClient.ts`, since ace-controller and miranda-transport are different coexisting services per T1's topology. Decodes the real 312-byte MRD1 binary packet; cross-verified against actual Rust-encoded bytes via a new `miranda-transport/examples/emit_test_packet.rs`, not just self-consistent TS. Caught and fixed a real landmine: the pre-existing `ARKIT_CHANNELS` array in `types.ts` is in a different order than `miranda-core::arkit::CHANNEL_NAMES`; added `ARKIT_CANONICAL_ORDER` copied verbatim from Rust as the only array the decoder may index against. `spatialSyncer.ts` deliberately left un-coupled to server telemetry timestamps — documented why (decoupled-render-loop guardrail).
- [x] [CAT 3] Verify `src/lib/stageMachine/` L0/L1/L2 logic still applies cleanly to the new backend, or adapt it. — Found and fixed a real design gap: `StageContract.hotNodes` required ALL listed nodes hot (AND semantics), which after T1's rewrite meant L1 required both `cloud-bridge` (Pipeline 1) AND `kinematics`/`native-capture` (Pipeline 2) — so a Pipeline-1-only session, the live one today, could never reach L1. Added `hotNodeAlternatives: string[][]` (OR-within-group semantics) to `StageContract`; `stageReadiness`/`healthForStageRole`/`presenceStore.ts`'s warm-pull logic all updated to honor it. 15 new vitest unit tests pin down both single-pipeline-reaches-L1 cases plus the previously-broken both-cold case. `npx vitest run`: 15/15 pass.
- [x] [CAT 5] Build the new WebGPU viewport component (WGSL shaders, DataChannel frame ingestion, Gaussian-splat deformation). **Opus 5 only** — genuinely novel graphics-shader engineering, the least-precedented task in the entire project. — Done on Sonnet 5 per user's standing "relieve CAT-5 protocol" instruction; no escalation needed. `SplatRenderer.ts` + `shaders.wgsl.ts`: two-pass deform-compute + billboard-render pipeline, decoupled render loop (rAF independent of network arrival — SplatViewport polls mirandaTransport.getLastFrame() on its own tick, never via React state). Real WGSL bug found via GPU validation error (pushErrorScope) and fixed: layout:"auto" drops bindings that are declared but never read in the shader body ("binding index 2 not present in the bind group layout"). Verified on real Intel UHD hardware via off-screen COPY_SRC texture readback: zero validation errors, real clear-color and splat-color pixels confirmed, and jawOpen measurably moves jaw-region splat positions in isolated compute-pass-only readback.
- [x] [CAT 2] Source or stub a placeholder Gaussian-splat asset to develop the viewport against while the real GaussianAvatars/FLAME/TetGS pipeline (`live-avatar-expert` skill) is built separately. — `placeholderSplat.ts`: deterministic (seeded) procedural head-shaped splat cloud with the standard per-splat attribute set (position/scale/rotation/color/opacity) plus per-splat jaw/eyelid skinning weights, so it exercises the deform shader meaningfully rather than sitting inert. A real trained asset drops in as a data swap, not a renderer rewrite.
